# AI / inference unit costs for hosted Jarvis Consumer (research R3)

**Date:** 2026-10-28 · **Status:** research only, NO decision, NO spend, NO account, NO API call, nothing run ·
**Related:** ADR-0059 (hosted consumer design, sections 1 and 6), ADR-0050 (budget model)

All "accessed" dates below are **2026-10-28** unless stated. Prices are copied as published, in the currency shown
(mostly USD; EU providers EUR/CHF), **excluding VAT**. No FX rate is documented here, so USD and EUR are never mixed in
arithmetic. Anything not read on a vendor's own page is marked **unverified (third party)**. Anything not found is
**NOT FOUND**. Nothing is guessed.

## 0. How this was gathered, and honest limits

- Only public web pages were read (WebFetch/WebSearch). WebFetch passes each page through a small summarizing model,
  so a number can be mis-transcribed: **every figure must be re-checked on the live page before any decision.**
- Several vendor pages returned 403/404, were truncated, or did not render their price tables (listed in section 9).
- Model names/versions (for example "Claude Haiku 5.5", "gpt-6-luna", "Gemini 3.8 Flash") are reproduced exactly as the
  pages showed them on the access date; they were not independently confirmed.
- Prices change often; some listed here have **announced step-ups** (Gemini, section 3.3).
- Quality of tool use / computer use is **not rated** here. Only statements quoted from official docs are included.
- The scenarios in section 6 are **assumptions**, not measurements. Real usage is unknown (ADR-0059 section 6).
- The AGENTS.md "done gate" script was not run (owner ban on running code).

- Prices: section 1. Cache multipliers: 5-min write 1.25x, 1-hour write 2x, read 0.1x (0.05x on Sonnet 5.5 and Opus 5.5;
  0.025x on Fable 5.1). Batch API: 50% on input and output, stacks with caching. Haiku 5.5 is priced by prompt length:

- Tool use: an automatic tool-use system prompt is added: Haiku 5.5 286 tokens, Sonnet 5.5 286, Opus 5.5 286 (same page).
  Web search tool: $10 per 1,000 searches plus tokens.

## 6. AI cost per customer (formula, documented prices only)

### 6.1 Formula
Monthly AI cost = sum over models m of share_m x ( W x p_write(m) + R x p_read(m) + U x p_in(m) + O x p_out(m) ) +
voice minutes x (STT/min + TTS/min) [or realtime/min]. W, R, U, O are millions of tokens per month: cache-write,
cache-read, uncached input, output. Where a vendor shows no cache-write price, **write is assumed to cost the normal
input price** (assumption). Where a vendor shows no cache read price, the combo is not used.

### 6.2 Assumptions (all are assumptions, none measured; 30 days/month)
- Agent turn = 3 model calls (2 tool steps + final answer). Per call: 8,000 input tokens of which a 6,000-token prefix
  (system prompt + tool definitions + memory) is cacheable, 2,000 new tokens; 400 output tokens.
  Per turn with caching: first call writes 6,000 (W), calls 2 and 3 read 12,000 (R), uncached 6,000 (U), output 1,200 (O).
  Without caching the same turn is 24,000 input tokens.
- Browser/computer-use step = 1 call: one 1280x720 screenshot = ceil(1280/28) x ceil(720/28) = 46 x 26 = 1,196, taken as
  1,200 tokens (formula from Anthropic vision doc; other vendors' image token counts NOT FOUND, so the same count is
  assumed for all combos) + 2,000 other uncached tokens; prefix 6,000 read from cache; output 200. So per step:
  U 3,200, R 6,000, O 200.
- Scenarios: **light** 20 turns/day (600/month), 5 browser steps/day (150), 0 voice min; **medium** 80 turns/day
  (2,400), 30 steps/day (900), 60 voice min/month; **intense** 250 turns/day (7,500), 100 steps/day (3,000), 300 voice
  min/month (voice minutes follow ADR-0059 section 6 so the two documents agree).
- Routing: 90% of tokens on the cheap model, 10% on the stronger model (assumed split, not measured).
- Voice (cascaded, assumed 1 min STT + 1 min TTS per voice minute, 900 characters of speech per minute):
  Voxtral Mini Transcribe 3 $0.0035 + Voxtral TTS 3 (13 x 900 / 1,000,000 = $0.0117) = **$0.0152 per voice minute**.
  Cheaper cascade: Groq whisper-large-v3-turbo $0.000667 + Together Kokoro (4 x 900/1e6 = $0.0036) = $0.0043 per minute
  (Kokoro quality and Groq retention not assessed). LLM tokens of voice turns are assumed already inside the turn count.
- Not included: VAT, payment fees, embeddings (memory indexing assumed <= 1M tokens/month = under $0.2 at the prices in
  section 2), web-search tool fees, storage, hosting, retries, long prompts (>100k), image generation.

### 6.6 Effect of caching and batch (documented multipliers)
- Without caching (all input at base price), combo B light = 0.9x(15.78x0.10+0.375) + 0.1x(15.78x2+7.5) =
  0.9x1.953+0.1x39.06 = **5.66** vs 3.73 with caching (+52%); medium **23.54** vs 15.32; intense **74.12** vs 48.12.
  So with the assumed 6,000-token cacheable prefix, caching saves about one third of the bill. The saving depends on
  the 5-minute TTL: a customer idle >5 minutes pays a new write. 1-hour writes cost 2x (Anthropic) and were not modelled.
- Anthropic: pruning screenshots one per turn breaks the cache (computer-use doc), so prune in batches.
- Batch (50% on Anthropic, OpenAI, Gemini, Mistral generic) applies only to asynchronous work (for example overnight
  memory consolidation, summaries, embedding rebuilds), not to interactive chat; no share of work was assumed async here,
  so no batch discount is applied above. Example: Haiku 5.5 batch is 0.05 / 0.25.
- Anthropic data residency: `inference_geo: "us"` is +10% (only US/global exist, section 3.1).

### 6.7 Sensitivity the owner should see
- The strong-model share dominates: in combo B intense, 10% of tokens on Sonnet 5.5 is $32.85 of $48.12. At 0% (A) the
  same usage is $16.97.
- Opus 5.5 / Fable 5.1 as "occasional stronger model" cost 2x and 5x the Sonnet 5.5 line, respectively (list prices).
- ADR-0059 target is 25-30 EUR per customer for hosting + AI. Compare only after an FX rate is chosen; in nominal
  numbers the intense scenario with a Sonnet-class router exceeds 30 even before hosting; light and medium fit.

## 7. Subscription vs API: ToS statements

A consumer subscription (ChatGPT, Claude, Gemini plans) is **not** API credit. Nothing was scraped, accessed, or used.
- **Anthropic** (primary, read): Help Center: paid Claude plans are "separate products" from the Claude Console and "the
  Claude API is billed separately" (support.claude.com article 9876003). Consumer Terms: no access through "automated or
  non-human means" such as bots or scripts "unless you use an Anthropic API key or Anthropic explicitly permits it"; "You may
  not share your Account login information, Anthropic API key, or Account credentials with anyone else"; no reselling the
  Services or building competing products (anthropic.com/legal/consumer-terms, sections 2-3 as summarized by the fetch
  tool). Commercial Terms: no resale "except as expressly approved by Anthropic" (D.4); customers may power products for their own
  users (A.1) via API keys (anthropic.com/legal/commercial-terms). **Conclusion supported by these quotes: a subscription
  login cannot be used server-side for other customers; the API under Commercial Terms is the path.** (Legal reading is not
  provided here.)
- **OpenAI**: primary Terms of Use pages returned 403 and the help page returned 403. Search results (third party,
  **unverified**) say the consumer terms ban automatic/programmatic extraction and copying/leasing/selling the Services, and
  that a ChatGPT subscription does not itself provide API access. Primary text: NOT FOUND.
- **Google**: primary text for Gemini Apps/Google AI Pro NOT FOUND. A Google community moderator reply and forum posts
  (third party, **unverified**) say Google AI Pro provides no Gemini API quota/credits and API billing is separate. The

- Other vendors (xAI, Mistral Le Chat, etc.): not researched for consumer-plan ToS: NOT FOUND.

## 8. Cost control mechanisms (options, not decisions)

1. **Hard per-customer ledger caps**, already in ADR-0059 section 6 (reserve worst case, block before spend, no automatic
   overage). Provider-side caps that exist: Anthropic org spend cap and per-workspace limits (workspaces can carry their
   own spend limits, but not on the default workspace); OpenAI monthly usage limit by tier; Gemini billing-tier cap. These
   are organization-level, not per customer: they protect the operator, not each tenant.
2. **Router small -> large**: default to a Haiku/Mini/Small class model; escalate on task type, tool failure or user
   request. Section 6.7 shows the escalation share is the main cost lever.
3. **Prompt caching**: stable prefix first (system prompt, tools, memory summary), measured cache-hit rate in the ledger;
   batch-prune screenshots; consider 1-hour writes only if idle gaps exceed 5 minutes and re-reads >= 2.
4. **Screenshot discipline for browser steps**: lower resolution (docs recommend 1280x720; avoid >1920x1080), crop, keep
   only last N screenshots, text/DOM extraction before vision where possible. High-resolution tier costs up to ~3x tokens
   per image (vision doc).
5. **Batch for async jobs** (memory consolidation, indexing) at documented -50%.
6. **Local/own models for cheap steps** (classification, routing, summarization, embeddings, STT): either on the
   customer's device (ADR-0049 style, outside this research), or a rented GPU/EU endpoint (section 4); fixed monthly cost
   vs per-token, throughput NOT FOUND.
7. **Per-customer limits on turns/day, tool steps per turn, max output tokens, voice minutes**; refuse unknown-price
   models (ADR-0059 section 6 rule 3).
8. **Prefer the cheaper voice path**: cascaded STT + TTS at ~$0.004-0.015 per minute vs realtime APIs at $0.04-0.08 per
   minute (3-10x), per sections 2 and 6.5.
9. **Avoid the free tiers** for production tenants (data-use terms, section 5).
10. **Provider diversification / OpenRouter** for failover: no per-token markup stated, but credit fee amount NOT FOUND and
    privacy depends on routed provider; adds a processor to the DPA chain.
